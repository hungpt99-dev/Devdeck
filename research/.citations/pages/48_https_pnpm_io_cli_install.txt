# pnpm install

Aliases: `i`

`pnpm install` is used to install all dependencies for a project.

Package manifests and archive metadata larger than 64 MiB are rejected.

In a CI environment, installation fails if a lockfile is present but needs an update. To allow lockfile updates in CI, run `pnpm install --no-frozen-lockfile`.

Inside a [workspace](https://pnpm.io/workspaces), `pnpm install` installs all dependencies in all the projects. If you want to disable this behavior, set the [`recursiveInstall`](https://pnpm.io/settings/cli#recursiveinstall) setting to `false`.

When a workspace project changes, unchanged direct dependencies in other projects keep their locked versions if those versions still satisfy their declared ranges. Use [`pnpm update`](https://pnpm.io/cli/update) to request dependency updates.

Changes to a workspace package's `bin` field are linked into its dependents' `node_modules/.bin` on the next install, even with `--frozen-lockfile` and an unchanged lockfile.

![](https://pnpm.io/docs-assets/12.x/img/demos/pnpm-install.svg)

## TL;DR#

| Command | Meaning |
|---|---|
| `pnpm i --offline` | Install offline from the store only |
| `pnpm i --frozen-lockfile` | `pnpm-lock.yaml` is not updated |
| `pnpm i --lockfile-only` | Only `pnpm-lock.yaml` is updated |
| `pnpm i --dry-run` | Preview changes without writing |

## Options for filtering dependencies#

Without a lockfile, pnpm has to create one, and it must be consistent regardless of dependencies filtering, so running `pnpm install --prod` on a directory without a lockfile would still resolve the dev dependencies, and it would error if the resolution is unsuccessful. The only exception for this rule are `link:` dependencies.

Without `--frozen-lockfile`, pnpm will check for outdated information from `file:` dependencies, so running `pnpm install --prod` without `--frozen-lockfile` on an environment where the target of `file:` has been removed would error.

### --prod, -P#

- Default: **false**
- Type: **Boolean**

If `true`, pnpm will not install any package listed in `devDependencies` and will remove those insofar they were already installed. If `false`, pnpm will install all packages listed in `devDependencies` and `dependencies`.

### --dev, -D#

Only `devDependencies` are installed and `dependencies` are removed insofar they were already installed.

### --no-optional#

`optionalDependencies` are not installed.

### --optional#

Install `optionalDependencies` even when the [`optional`](https://pnpm.io/settings/dependency-resolution#optional) setting excludes them.

### --no-runtime#

Skip installing runtime entries (e.g. Node.js downloaded via [`devEngines.runtime`](https://pnpm.io/package_json#devenginesruntime)). The lockfile is left untouched, so frozen installs still validate; only the runtime fetch and bin-linking are skipped. A runtime that an earlier install linked is removed from `node_modules`.

This is useful in CI matrices where the runtime is provisioned externally (e.g. via `pnpm runtime -g set node <version>`) before `pnpm install` runs.

This can also be set with `runtime: false` in `pnpm-workspace.yaml`.

## Options#

### --ignore-workspace#

Install the current project as a standalone project, without discovering a `pnpm-workspace.yaml` in a parent directory. The workspace's settings and other projects do not apply. See the [`--ignore-workspace` global option](https://pnpm.io/pnpm-cli#--ignore-workspace).

### --force#

Force reinstall dependencies: refetch packages modified in store, recreate a lockfile and/or modules directory created by a non-compatible version of pnpm. `--force` also lifts [`engineStrict`](https://pnpm.io/settings/cli#enginestrict).

Since v12.7.0, `--force` no longer installs optional dependencies whose `os`, `cpu`, or `libc` do not match the host. Set [`forceIgnoresPlatform`](https://pnpm.io/settings/dependency-resolution#forceignoresplatform) to `true` to install them anyway.

### --offline#

- Default: **false**
- Type: **Boolean**

If `true`, pnpm will use only packages already available in the store. If a package won't be found locally, the installation will fail.

### --no-offline#

Allow network requests even when the `offline` setting is `true`.

### --prefer-offline#

- Default: **false**
- Type: **Boolean**

If `true`, staleness checks for cached data will be bypassed, but missing data will be requested from the server. To force full offline mode, use `--offline`.

### --no-prefer-offline#

Don't prefer cached data even when the `preferOffline` setting is `true`.

### --no-lockfile#

Don't read or generate a `pnpm-lock.yaml` file.

### --lockfile-only#

- Default: **false**
- Type: **Boolean**

When used, only updates `pnpm-lock.yaml` and `package.json`. Nothing gets written to the `node_modules` directory.

### --lockfile-dir <dir>#

The directory in which `pnpm-lock.yaml` is created. Several projects can share one lockfile. It cannot be combined with `--global`.

### --dry-run#

Run a full dependency resolution and report what a real install would change, without writing anything to disk. No lockfile, manifest, or `node_modules` changes are saved.

A completed dry run exits with code 0, even when it reports that a real install would update the lockfile.

`--dry-run` cannot be used with a configured pnpr server, because that install path resolves and links through the server.

### --fix-lockfile#

Fix broken lockfile entries automatically.

### --update-checksums#

Re-resolve every locked package and record the integrity the registry reports now in `pnpm-lock.yaml`. Use it when a registry rewrote its tarballs, or after a registry starts serving [tars](https://pnpm.io/registries#tar-registries).

By default, an integrity mismatch is a hard failure: `pnpm install` exits with `ERR_PNPM_TARBALL_INTEGRITY` rather than silently re-resolving from the registry and overwriting the locked integrity. This protects projects that ship a committed lockfile from a compromised registry, proxy, or republished version substituting attacker-controlled content on a clean machine.

`--update-checksums` is the narrowly-scoped opt-in for the legitimate case (e.g. a registry rewrote its tarballs and you've verified the new bytes are correct). A warning still prints when the bypass takes effect so the operation is auditable.

`--force` and `pnpm update` deliberately do **not** bypass the integrity check. `--frozen-lockfile` is unchanged, and `--fix-lockfile` keeps its documented purpose (filling in missing lockfile entries) and is also not a bypass.

### --frozen-lockfile#

- Default:
  - For non-CI: **false**
  - For CI: **true**, if a lockfile is present
- Type: **Boolean**

If `true`, pnpm doesn't generate a lockfile and fails to install if the lockfile is out of sync with the manifest / an update is needed or no lockfile is present.

This setting is `true` by default in [CI environments](https://github.com/watson/ci-info#supported-ci-tools). pnpm detects a CI environment with the same rules as the [ci-info](https://github.com/watson/ci-info) package. Set `CI=false` to turn detection off.

### --no-frozen-lockfile#

Allows lockfile updates during installation. This is the inverse of `--frozen-lockfile`.

### --prefer-frozen-lockfile#

Use the existing lockfile without re-resolving, even when the manifest might have changed. The inverse is `--no-prefer-frozen-lockfile`, which always re-resolves against the registry. See [`preferFrozenLockfile`](https://pnpm.io/settings/store#preferfrozenlockfile).

### --ignore-manifest-check#

Skip the check that `pnpm-lock.yaml` is up to date with `package.json` under `--frozen-lockfile`. Use it only when you just wrote the lockfile yourself.

### --trust-lockfile#

Skip verifying the lockfile against supply-chain policies. `--no-trust-lockfile` verifies it even when the configuration trusts it. See [`trustLockfile`](https://pnpm.io/settings/dependency-resolution#trustlockfile).

### --auto-dedupe#

Deduplicate compatible dependency versions during installation. `--no-auto-dedupe` turns it off when the configuration turns it on. See [`autoDedupe`](https://pnpm.io/settings/dependency-resolution#autodedupe).

### --merge-git-branch-lockfiles#

Merge all git branch lockfiles. [Read more about git branch lockfiles.](https://pnpm.io/git_branch_lockfiles)

### --merge-git-branch-lockfiles-branch-pattern <glob>#

Merge the git branch lockfiles when the current branch matches the pattern. The option can be repeated. See [`mergeGitBranchLockfilesBranchPattern`](https://pnpm.io/settings/store#mergegitbranchlockfilesbranchpattern).

### --reporter=<name>#

- Default:
  - For TTY stdout: **default**
  - For non-TTY stdout: **append-only**
- Type: **default**, **append-only**, **ndjson**, **silent**

Allows you to choose the reporter that will log debug info to the terminal about the installation progress.

- **silent** - no output is logged to the console, not even fatal errors
- **default** - the default reporter when the stdout is TTY
- **append-only** - the output is always appended to the end. No cursor manipulations are performed
- **ndjson** - the most verbose reporter. Prints all logs in [ndjson](https://github.com/ndjson/ndjson-spec) format. Fatal error records include the error code. Dependency resolution errors also include the parent packages in `pkgsStack`.

If you want to change what type of information is printed, use the [loglevel](https://pnpm.io/settings/cli#loglevel) setting.

### --shamefully-hoist#

- Default: **false**
- Type: **Boolean**

Creates a flat `node_modules` structure, similar to that of `npm` or `yarn`. **WARNING**: This is highly discouraged.

### --ignore-scripts#

- Default: **false**
- Type: **Boolean**

Do not execute any scripts defined in the project `package.json` and its dependencies.

### --no-ignore-scripts#

Run lifecycle scripts even when the `ignoreScripts` setting is `true`.

### --ignore-pnpmfile#

Don't load the hooks in `.pnpmfile.cjs`, including the pnpmfiles of config dependencies.

### --node-linker <linker>#

- Type: **isolated**, **hoisted**, **pnp**

Override the [`nodeLinker`](https://pnpm.io/settings/node-modules#nodelinker) setting for this install.

### --frozen-store#

Open the store read-only and skip all store writes, for a store on a read-only filesystem. Use it with `--offline --frozen-lockfile`. `--no-frozen-store` allows store writes when the configuration turns the read-only store on. See [`frozenStore`](https://pnpm.io/settings/store#frozenstore).

### --network-concurrency <number>#

Override the [`networkConcurrency`](https://pnpm.io/settings/network#networkconcurrency) setting.

### --fetch-timeout <ms>#

Override the [`fetchTimeout`](https://pnpm.io/settings/network#fetchtimeout) setting.

### --fetch-warn-timeout-ms <ms>#

Override the [`fetchWarnTimeoutMs`](https://pnpm.io/settings/network#fetchwarntimeoutms) setting.

### --fetch-min-speed-ki-bps <number>#

Override the [`fetchMinSpeedKiBps`](https://pnpm.io/settings/network#fetchminspeedkibps) setting.

### --user-agent <string>#

The `User-Agent` header to send with registry requests.

### --pnpr-server <url>#

Override the [`pnprServer`](https://pnpm.io/settings/dependency-resolution#pnprserver) setting.

### --allow-build#

Added in: v12.7.0

Allow the named package to run its lifecycle scripts during this install, and record it in the [`allowBuilds`](https://pnpm.io/settings/build#allowbuilds) field of `pnpm-workspace.yaml` so it stays allowed. Prefix a name with `!` to deny its scripts instead. The option can be repeated:

```sh
pnpm install --allow-build=esbuild --allow-build='!core-js'
```

The quotes keep a POSIX shell from treating `!` as history expansion. In Windows `cmd.exe`, leave them out.

writes:

pnpm-workspace.yaml

```yaml
allowBuilds:
  esbuild: true
  core-js: false
```

### --filter <package_selector>#

### --cpu=<name>#

Override CPU architecture of native modules to install. Acceptable values are same as `cpu` field of `package.json`, which comes from `process.arch`.

### --os=<name>#

Override OS of native modules to install. Acceptable values are same as `os` field of `package.json`, which comes from `process.platform`.

### --libc=<name>#

Override libc of native modules to install. Acceptable values are same as `libc` field of `package.json`.
