# Security

We think security is very important and are working on improving the security of aqua. aqua should allow you to install and execute tools securely. In this page, we describe aqua's security perspective.

## List of Issues and Pull Requests​

## Features​

- Design
  - aqua doesn't execute external commands except for `go install` and `go build` to install packages
    - This prevents malicious commands from being executed
  - Centrally managed Registry is provided
    - Compared with third party registries, it has low risk to be tampered
- [Checksum Verification](https://aquaproj.github.io/docs/reference/security/checksum)
- [Policy as Code](https://aquaproj.github.io/docs/reference/security/policy-as-code/)
  - [Only standard registry is allowed by default (Secure by default)](https://aquaproj.github.io/docs/reference/upgrade-guide/v2/only-standard-registry-is-allowed-by-default)
- [ghtkn integration](https://aquaproj.github.io/docs/reference/security/ghtkn)
- [Cosign and SLSA Provenance](https://aquaproj.github.io/docs/reference/security/cosign-slsa)
- [Minisign](https://aquaproj.github.io/docs/reference/security/minisign)
- [packslip](https://aquaproj.github.io/docs/reference/security/packslip)
- [GitHub Artifact Attestations](https://aquaproj.github.io/docs/reference/security/github-artifact-attestations)
- [GitHub Immutable Releases](https://aquaproj.github.io/docs/reference/security/github-immutable-release)
  - ⚠️ This feature was abandoned at aqua v2.60.1 [#4862](https://github.com/aquaproj/aqua/issues/4862)
- [Manage a GitHub access token using Keyring](https://aquaproj.github.io/docs/reference/security/keyring)
